# MCP SOAP Chat

A React/TypeScript chat web app for interacting with MCP SOAP servers generated by **wsdl-to-mcp**. Supports OAuth 2.0 token gateways and any OpenAI-compatible LLM endpoint.

## Features

- **OpenAI-compatible LLM** — works with OpenAI, Azure OpenAI, Ollama, vLLM, LM Studio, or any gateway
- **OAuth 2.0** — client credentials, authorization code, and resource owner password grants; tokens stored in memory only (secrets never persisted)
- **MCP tools** — connects to a running MCP server via HTTP/SSE transport; discovered tools are automatically passed to the LLM as function-calling tools
- **Streaming** — real-time streaming responses with stop button
- **Tool call visualization** — expandable panels show arguments and JSON results inline
- **Markdown rendering** — assistant responses rendered as GitHub-flavored markdown

## Quick Start

```bash
cd chat-app
npm install
npm run dev
# Opens at http://localhost:5174
```

## Configuration

Open the settings sidebar (⚙ icon) and configure three tabs:

### LLM Tab

| Field | Description |
|-------|-------------|
| Base URL | OpenAI-compatible endpoint, e.g. `https://api.openai.com/v1` |
| Model | Model name, e.g. `gpt-4o`, `llama3`, `mistral` |
| Authentication | Use OAuth token (recommended for gateways) or a static API key |
| Max Tokens | Maximum completion tokens |
| Temperature | Sampling temperature 0–2 |
| System Prompt | Prepended to every conversation |
| Extra Headers | Additional HTTP headers (e.g. `X-Api-Version`) |

### OAuth Tab

Configure when your LLM endpoint is behind an API gateway that requires session tokens.

| Field | Description |
|-------|-------------|
| Grant Type | `client_credentials` (default), `authorization_code`, or `password` |
| Token URL | Gateway token endpoint, e.g. `https://auth.example.com/oauth/token` |
| Client ID | OAuth client identifier |
| Client Secret | Secret (stored in memory only, never in localStorage) |
| Scope | Space-separated scopes, e.g. `api:read model:inference` |
| Extra Headers/Params | Additional fields for the token POST request |

Click **Fetch token** to obtain an access token. The app auto-refreshes before expiry.

### MCP Tab

Connect to a running MCP SOAP server generated by wsdl-to-mcp.

| Field | Description |
|-------|-------------|
| Server URL | HTTP base URL of the MCP server, e.g. `http://localhost:3000` |
| Auth Token | Optional bearer token if the MCP server requires auth |
| Auto-reconnect | Reconnect automatically if the connection drops |

#### Running the MCP Server with HTTP Transport

The generated server uses stdio transport by default. Bridge it to HTTP/SSE using one of these approaches:

**Option 1 — mcp-proxy** (simplest)
```bash
cd my-generated-mcp-server
npm install
# In one terminal:
npm run build && node dist/index.js
# The proxy wraps stdio with HTTP/SSE:
npx mcp-proxy --port 3000 -- node dist/index.js
```

**Option 2 — Add HTTP transport to the generated server**

Edit the generated `src/index.ts` to use `StreamableHTTPServerTransport` instead of (or in addition to) `StdioServerTransport`:

```typescript
import { StreamableHTTPServerTransport } from '@modelcontextprotocol/sdk/server/streamableHttp.js'
import express from 'express'

const app = express()
app.use(express.json())

const transport = new StreamableHTTPServerTransport({ sessionIdGenerator: undefined })
app.all('/mcp', async (req, res) => {
  await transport.handleRequest(req, res, req.body)
})
server.connect(transport)
app.listen(3000)
```

## Architecture

```
chat-app/src/
├── types/index.ts          # All TypeScript interfaces (OAuth, LLM, MCP, Chat)
├── store/index.ts          # Zustand stores (config, auth, mcp, chat, ui)
├── services/
│   ├── oauth.ts            # RFC 6749 token fetch/refresh/exchange
│   ├── mcp-client.ts       # MCP HTTP+SSE client (JSON-RPC)
│   └── llm-client.ts       # OpenAI-compatible streaming + tool calling
├── hooks/
│   ├── useOAuth.ts         # Token lifecycle management
│   ├── useMcpClient.ts     # MCP connection + tool calling
│   └── useChat.ts          # Conversation orchestration (LLM + tool loop)
└── components/
    ├── ConfigPanel.tsx      # Settings sidebar (LLM / OAuth / MCP tabs)
    ├── ChatInterface.tsx    # Message list + input
    ├── MessageBubble.tsx    # Individual message with markdown
    ├── ToolCallDisplay.tsx  # Expandable tool call + result panels
    └── ConnectionStatus.tsx # Status indicator dots
```

## Security Notes

- **Client secrets and API keys are never persisted to localStorage** — only non-sensitive config (URLs, model names, etc.) is saved
- Secrets live in Zustand memory only and are cleared on page refresh
- CORS: configure your LLM gateway and MCP server to allow requests from `http://localhost:5174` in development; in production set appropriate CORS headers

## Build for Production

```bash
npm run build
```
